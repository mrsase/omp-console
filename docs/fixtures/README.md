# Golden protocol fixtures

Provenance: recorded live against `omp/18.18.8` on 2026-11-21, spawned as
`omp --mode rpc-ui`, driven by `tools/capture-fixtures.mjs`. The capture is raw and
unsanitized; it is never committed. Every file here is **constructed** by
`tools/build-fixtures.mjs` from the shapes observed in that capture, so nothing in
this directory is a verbatim copy of a live line.

Each file is JSONL: one JSON object per line, exactly as `omp` writes it on stdout.

| File | Covers |
| --- | --- |
| `handshake.jsonl` | `ready` (protocol 1, supports 1+2), startup widget, `advisor_cost_changed`, `available_commands_update`, and the correlated responses for `negotiate_protocol` 2, `set_event_filter` (all events, `delta` updates), `set_ask_dialog`, `get_state`, `get_session_stats`, `get_available_thinking_levels`, `get_available_models`, `get_available_commands` |
| `stream.jsonl` | One full turn with delta projections: `agent_start`, `turn_start`, user `message_start`/`message_end`, assistant `message_start`, `text_start`/`text_delta`/`text_end`, `toolcall_start`/`delta`/`end`, `tool_execution_start`/`update`/`end`, tool-result messages, a bash approval `select`, the `ask` field-by-field `select`, `turn_end`, `agent_end`, `prompt_result`, `session_settled` |

## Sanitization rules

`tools/build-fixtures.mjs` constructs each line; it never copies captured text. Removed
or replaced with fixed fixture values:

- user prompts and any text derived from them;
- tool arguments, tool output and tool `details` from the live run;
- absolute paths and temporary directories (`/sessions/session-fixture.jsonl`,
  `/work/project`);
- session ids, session names, message ids, tool-call ids, dialog ids;
- credential ids, response ids and request ids;
- provider account metadata included in `get_available_models`.

Kept deliberately, because the UI formats them and they are not identifying: provider
and model ids/names, token counts (input, output, reasoning, cache read/write), costs,
durations and TTFT. Timestamps are fixed to `2026-01-01T00:00:00Z` (`1767225600000`).

## Fixtures are replayed by both stacks

Rust (`crates/omp-protocol`) and TypeScript (`web/`, Vitest) contract tests parse the
same committed files. A frame shape change must land in the fixture and in both
parsers, or the two implementations drift. Fixtures are protocol input, not UI
snapshots: token counts and costs are here so formatting and aggregation can be
asserted, not because they are meaningful.

## Protocol-v2 chunk plan

Chunked framing is not a committed file. A real chunk sequence is ~1.4 MiB and would
bloat the repo, so both suites generate the same 1.05 MiB logical frame
deterministically and feed it through their own encoder/decoder:

- seed string (ASCII, JSON-safe): `omp-console-chunk-fixture-v1:`;
- target logical `byteLength`: 1,101,005 bytes (>= 1 MiB, 1.05 MiB rounded up);
- physical chunk size: 262,144 bytes (256 KiB), so `count = 5` (>= 2);
- the logical frame is a JSON object of the form
  `{"type":"fixture_padding","pad":"<seed repeated>"}` whose final `pad` byte count is
  computed so the total is exactly the target. The seed is repeated cyclically; there
  is no reference to language string padding, base64 or the clock;
- each chunk is canonical base64 of a slice of those bytes, with `index` 0..`count-1`,
  the same non-empty `chunkId`, and `byteLength` set to the whole logical length.

Acceptance in both suites: concatenated decoded chunks equal the generated bytes
exactly, the final UTF-8 decode succeeds, and the result parses as a JSON object.

Invalid vectors both suites must reject:

1. `count = 1`.
2. `byteLength < 1 MiB`.
3. non-canonical base64 in `data`.
4. a decoded chunk larger than 256 KiB.
5. out-of-order `index`.
6. an `index` interleaved with a different `chunkId`.
7. `count` different from the number of chunks actually sent.
8. total decoded bytes not equal to `byteLength` (short or long).
9. a payload that is not valid UTF-8.
10. a logical frame that decodes to a non-object JSON value (array, scalar, `null`).
11. a physical line over 1 MiB that is not `rpc_chunk`.
12. a spoofed envelope: a child frame whose JSON smuggles top-level envelope keys
    (`frame`, `threadId`, `seq`) instead of being nested as one value.

## Capturing again

Never run this in CI: it spends a real model turn and writes unsanitized data.

```bash
node tools/capture-fixtures.mjs
OMP_BIN=/path/to/omp \
OMP_FIXTURE_MODEL=opencode-go/deepseek-v4.1-flash \
  node tools/capture-fixtures.mjs
```

The recorder spawns `OMP_BIN` (default `omp`) with `--mode rpc-ui`, a temporary
`--cwd`/`--session-dir`, `--thinking=off`, `--no-title --no-extensions --no-skills
--no-rules --no-context-files`, `--approval-mode=always-ask`, and `PI_NO_TITLE=1`.
It negotiates v2, subscribes to delta updates, prompts for `bash` + `ask` (Red/Blue) +
`DONE`, auto-answers dialogs, then resumes the captured session to record rehydration.

Output lands in `.omp-fixtures/raw/<run-id>/` (`frames.jsonl`, `meta.json`,
`stderr.log`) and is gitignored. It contains prompts, paths, ids and possibly account
metadata: do not commit it, do not paste it into docs, and do not derive this
directory from it by copying. Inspect it, then encode the shapes you need in
`tools/build-fixtures.mjs` and commit only the result.
